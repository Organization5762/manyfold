# manyfold 0.1.42

manyfold 0.1.42 adds the first process-fault-tolerant local control plane,
authenticated cross-process links, and bounded peer discovery and membership.

## Features

- Adds a persistent three-process Raft development cluster backed by
  PySyncObj, with distinct process identities, ports, and durable directories.
- Proves leader loss, quorum re-election, continued commits, restart recovery,
  and log convergence in a real subprocess integration test.
- Adds bounded TCP PubSub/RPC framing with reconnect backoff, heartbeats,
  link-health snapshots, and explicit lifecycle management.
- Requires mutual TLS and certificate identity binding for production
  transport links. Cleartext transport is an explicit loopback-only
  development mode.
- Adds static, DNS/MagicDNS, and zeroconf-backed mDNS discovery. Discovery
  produces untrusted endpoints until transport authentication establishes a
  node identity.
- Adds bounded lease membership with incarnation-aware `alive`, `suspect`,
  `dead`, and `left` transitions.
- Removes the public `EventStream` and `StreamNode` compatibility types in
  favor of concrete PubSub/value APIs and the narrow `Subscribable` protocol.

## Try It

Start a persistent local cluster:

```sh
uv run manyfold-cluster --root .manyfold-dev-cluster
```

Application code can manage the same lifecycle directly:

```python
from manyfold.cluster import DevelopmentCluster

cluster = DevelopmentCluster.create(".manyfold-dev-cluster")
with cluster:
    leader = cluster.wait_for_leader()
```

## Boundaries

- The Raft harness replicates control-plane commands only. Ordinary
  `PubSubTopic` data remains process-local and is not durable or replicated.
- The one-host harness protects against a coordinator process failure, not
  host, disk, power, or network failure.
- mDNS is link-local. MagicDNS and ordinary DNS supply reachability candidates,
  not trusted cluster membership.
- This release does not claim SWIM gossip. Membership exposes bounded,
  incarnation-safe state suitable for a future authenticated probing and
  dissemination backend.
- The development cluster HTTP API is loopback-only and unauthenticated.
  Multi-host deployment must use the authenticated transport and a secured
  coordinator API.
